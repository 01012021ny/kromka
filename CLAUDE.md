# КРОМКА — контекст для агента

3D-конструктор одежды для дизайнера, работающего в эстетике современной авангардной / «архивной» моды
(Rick Owens, Julius, if six was nine, L.G.B., Number (N)ine, Ann Demeulemeester, 14th Addiction, KMRii, Balmain).
Главная идея — проектировать вещь так, чтобы почти не было отходов ткани: раскладка и отходы видны при любой правке.
Инструмент должен быть понятен начинающей швее и полезен опытному портному.

## Владелец и правила общения
- Язык интерфейса, документации и ответов — русский.
- Предпочитает плотные, сразу применимые результаты без лишних уточнений. План — в неделях, работа в агентном режиме.
- Объяснять изменения коротко и простыми словами: что поменялось для пользователя и зачем, без жаргона.
- Код открытый (MIT, `LICENSE`). Рабочая ветка — `main`; Pages публикуется из неё.
- Эстетика интерфейса — тёмная, редакционная (см. CSS-переменные в `src/template.html`).
- Цвета: **красный — всегда негатив, зелёный — всегда позитив**. Никогда не красить негативное зелёным
  (отходы, расхождение шва, перетяжка — красные; совпадение шва, хорошее использование ткани — зелёные).

## Сборка и проверка
```bash
npm ci
npm test          # обязательно перед каждым коммитом; ~20 с, 38+ проверок
npm run typecheck # проверка типов TypeScript (~1 с)
npm run build     # dist/index.html — один самодостаточный файл
npm run e2e       # сборка + Playwright-сценарии e2e/*.spec.js (~2 мин)
```
- `dist/index.html#local` — физика в основном потоке (для отладки и e2e).
- e2e: `e2e/fixtures.js` — `openApp`, `captureSaves`/`savedFiles` (перехват `app.save`), `clothStats`; любая ошибка страницы роняет тест.
  Нужен `npx playwright install chromium`; версия `@playwright/test` закреплена точно — браузер должен ей соответствовать.
- Типы: обычный JS + `// @ts-check` в начале файла (ядро уже под проверкой, `src/ui/` — ещё нет); типы — JSDoc,
  глобальные имена — `src/globals.d.ts`. Новый модуль — сразу с `// @ts-check`. Сборка (esbuild) от этого не зависит.
- CI (`.github/workflows/ci.yml`) гоняет типы, unit и e2e; `pages.yml` публикует на GitHub Pages только при зелёных unit и e2e.
- Нашёл баг в физике/лекалах — сначала регрессионный тест в `tests/suite.js`, потом исправление.

## Ограничения среды, которые надо сохранять
- Итог — один HTML-файл; внешние запросы запрещены (страница живёт и как артефакт Claude под CSP).
  Разрешены: инлайн-JS, Google Fonts, blob:-воркеры, file input.
- Сохранение файлов: `app.save()` — сначала `window.claude.use('downloads')` (артефакт Claude), иначе ссылка-blob.
  Допустимые расширения в артефакте: pdf, svg, json, html, png, zip, csv, txt (DXF/PLT — только внутри zip).
- localStorage — только удобство (автосейв), обёрнуто в try/catch.

| Модуль | Ответственность |
|---|---|
| `body.js` | мерки из пола/роста/веса/% жира (+ ручные), кольца торса (суперэллипс, отдельная глубина переда/спинки), конечности-капсулы, SDF (точный `sdfExact` и воксельный `sdf`, шаг 1,5 см) с плавным объединением |
| `patterns.js` | модель детали; генераторы `genTop / genPants / genSkirt / genSnood`; `splitEdge`, `cutPiece`, `duplicatePiece`, деформации, швы |
| `sim.js` | XPBD: 8 подшагов × 2 итерации; растяжение с анизотропией нити и косой, ограничение деформации, изгиб, шитьё, обручи горловин/поясов, ремни, трение Кулона, ткань–ткань |
| `simworker.js` / `simproxy.js` | физика в Web Worker; прокси с тем же API (`build/step/wake/grab/running`) |
| `materials.js` | волокна, переплетения, 48 основ, `physics(m)` выводит параметры из состава/плотности/обработки; текстуры |
| `grading.js` | градация: поле смещений между размерами базовой конструкции (IDW по соответствию сторон) переносит правки |
| `layout.js` | растровая раскладка bottom-left с несколькими порядками; `affine` — чистый поворот (без зеркала!) |
| `export.js` | PDF А4 1:1 (растровые листы, Flate), DXF (блоки AAMA, слои 1/4/7/8/14/15), PLT (HPGL), ZIP, SVG-веер |
| `editor2d.js` / `view3d.js` / `main.js` | 2D-редактор, 3D-вид, состояние и конвейер пересборки |
| `ui.js` + `ui/` | `ui.js` — вход (шапка, клавиши, реэкспорт API для `main.js`); `ui/controls` — `$`/`ctl`/`bindCtl`, `ui/toolbar` — инструменты 2D, `ui/left` — панели вкладок, `ui/inspector` — инспектор справа, `ui/status` — строка состояния, `ui/layoutview` — вид раскладки, `ui/exports` — меню «Файл» и диалог производства, `ui/help` |

## Соглашения о координатах (важно)
- Лекало: сантиметры, **y вверх = высота на теле** (деталь лежит на той высоте, где её носят). Полигоны CCW.
- Перед: x+ = левая сторона модели (мир +x). Спинка смотрится сзади: x+ = правая сторона модели (мир −x).
- Рукав: y = 0 — вершина оката, вниз отрицательно; x > 0 — передняя половина оката.
- Брючные половинки: x = 0 — линия заутюженной складки; левая передняя — шаг на −x.
- Шов `{a:{p,e}, b:{p,e}, rev}`: стороны задаются id начального угла; `rev` вычисляется по 3D-расстановке (`seamRev`).
- `piece.base` — имя исходной детали генератора (нужно градации), сохраняется при разрезе; `baseMirror` у зеркальных копий.
- Ткань → рулон: u — вдоль рулона (долевая), v — поперёк. Поворот 0/180°, для бумаги 90°.

## Проверенные решения и почему
- Обручи (hoop) только для «кольцевых» краёв (`RING_EDGES`: пояс, низ, низ рукава, горловина, пройма, край) —
  на большом контуре распашного пальто обруч стягивал вещь с плеч.
- Статическое трение обязательно: без него тяжёлое распашное пальто сползало под весом рукавов.
- Обёртка рукава/брючины нормирована по ширине ряда — иначе шов закрывался через руку и рука выходила из рукава.
- Руки манекена по умолчанию отведены на 24°: при 14° слои застревали в подмышке.

## Известные ограничения
- Самопересечение — частицами (радиус ~1,15 см), края/швы исключены. Тонкие складки ещё могут проходить.
- Раскладка — однослойная, жадная; 50–70 % для одной вещи, тираж из нескольких размеров заметно лучше.
- PDF растровый 150 dpi; векторный контур — в DXF/SVG.
- TypeScript — только проверка JSDoc в нестрогом режиме, UI пока без неё; нет WASM; решатель ~13–16 мс на шаг при 4,5 тыс. точек.
