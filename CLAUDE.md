# КРОМКА — контекст для агента

3D-конструктор одежды для дизайнера, работающего в эстетике современной авангардной / «архивной» моды
(Rick Owens, Julius, if six was nine, L.G.B., Number (N)ine, Ann Demeulemeester, 14th Addiction, KMRii, Balmain).
Главная идея — проектировать вещь так, чтобы почти не было отходов ткани: раскладка и отходы видны при любой правке.
Инструмент должен быть понятен начинающей швее и полезен опытному портному.

## Владелец и правила общения
- Язык интерфейса, документации и ответов — русский.
- Предпочитает плотные, сразу применимые результаты без лишних уточнений. План — в неделях, работа в агентном режиме.
- Объяснять изменения коротко и простыми словами: что поменялось для пользователя и зачем, без жаргона.
- Код **закрытый** (все права защищены, `LICENSE`; `package.json` — `UNLICENSED`). Репозиторий приватный, публичного деплоя нет.
  Предпросмотр — приватный артефакт Claude «КРОМКА — студия кроя» (slug `98285bb6-ce12-4855-a2d3-18ed305104ab`, публиковать `dist/index.html`).
  Рабочая ветка — `main`. Не возвращать GitHub Pages и не публиковать сборки публично без явной просьбы владельца.
- Эстетика интерфейса — тёмная, редакционная (см. CSS-переменные в `src/template.html`).
- Цвета: **красный — всегда негатив, зелёный — всегда позитив**. Никогда не красить негативное зелёным
  (отходы, расхождение шва, перетяжка — красные; совпадение шва, хорошее использование ткани — зелёные).

## Целевое железо и скорость (важно)
- Всё должно идти без лагов на ноутбуке владельца: **Intel i7-10510U + встроенная Intel UHD Graphics** (на нём он кодит и тестирует).
  Рабочий ПК мощнее, но ориентир — слабое железо: у большинства пользователей нет хорошей видеокарты.
- Тяжёлое — в фоновых потоках: физика (`simworker.js`), раскладка и подбор ширины (`layoutworker.js`). В основном потоке — только UI и отрисовка.
- 3D рисуется **по требованию** (`view3d.invalidate()`): кадр — когда двигается ткань/камера или что-то поменялось, в покое 4 к/с.
  Чёткость (pixel ratio) снижается сама при кадрах медленнее ~30 к/с. Новые правки сцены вне `View3D` — вызывать `invalidate`.
- `npm run bench` — замеры ядра. Бюджеты (машина разработки, 2 ядра): шаг физики джинсы + лонгслив ≤ 16 мс при ~4 тыс. точек,
  раскладка одного комплекта ≤ 300 мс (в фоне), генерация лекал ≤ 5 мс. Новая фича не должна ухудшать их заметно — замерить до/после.
- Продукт для продаж (аккаунты, оплата, онбординг) — в последнюю очередь; сначала инструмент, скорость, качество кроя.

## Сборка и проверка
```bash
npm ci
npm test          # обязательно перед каждым коммитом; ~50 с, 90+ проверок
npm run typecheck # проверка типов TypeScript (~1 с)
npm run build     # dist/index.html — один самодостаточный файл
npm run e2e       # сборка + Playwright-сценарии e2e/*.spec.js (~2 мин)
npm run bench     # замеры скорости физики, раскладки, градации
KROMKA_DEBUG=1 npm run build  # сборка без минификации — для профилирования
```
- `dist/index.html#local` — физика в основном потоке (для отладки и e2e).
- e2e: `e2e/fixtures.js` — `openApp`, `captureSaves`/`savedFiles` (перехват `app.save`), `clothStats`; любая ошибка страницы роняет тест.
  Нужен `npx playwright install chromium`; версия `@playwright/test` закреплена точно — браузер должен ей соответствовать.
- Типы: обычный JS + `// @ts-check` в начале файла (ядро уже под проверкой, `src/ui/` — ещё нет); типы — JSDoc,
  глобальные имена — `src/globals.d.ts`. Новый модуль — сразу с `// @ts-check`. Сборка (esbuild) от этого не зависит.
- CI (`.github/workflows/ci.yml`) гоняет типы, unit и e2e. Деплоя нет (Pages удалён при закрытии кода).
- Нашёл баг в физике/лекалах — сначала регрессионный тест в `tests/suite.js`, потом исправление.

## Ограничения среды, которые надо сохранять
- Итог — один HTML-файл; внешние запросы запрещены (страница живёт и как артефакт Claude под CSP).
  Разрешены: инлайн-JS, Google Fonts, blob:-воркеры, file input.
- Сохранение файлов: `app.save()` — сначала `window.claude.use('downloads')` (артефакт Claude), иначе ссылка-blob.
  Допустимые расширения в артефакте: pdf, svg, json, html, png, zip, csv, txt (DXF/PLT — только внутри zip).
- localStorage — только удобство (автосейв), обёрнуто в try/catch.

## Соглашения о координатах (важно)
- Лекало: сантиметры, **y вверх = высота на теле** (деталь лежит на той высоте, где её носят). Полигоны CCW.
- Перед: x+ = левая сторона модели (мир +x). Спинка смотрится сзади: x+ = правая сторона модели (мир −x).
- Рукав: y = 0 — вершина оката, вниз отрицательно; x > 0 — передняя половина оката.
- Брючные половинки: x = 0 — линия заутюженной складки; левая передняя — шаг на −x.
- Шов `{a:{p,e}, b:{p,e}, rev}`: стороны задаются id начального угла; `rev` вычисляется по 3D-расстановке (`seamRev`).
- `piece.base` — имя исходной детали генератора (нужно градации), сохраняется при разрезе; `baseMirror` у зеркальных копий.
- Ткань → рулон: u — вдоль рулона (долевая), v — поперёк. Поворот 0/180°, для бумаги 90°.
- `piece.inner` — внутренняя деталь (мешковина, откосок, шлёвки): кроится и экспортируется, в 3D не драпируется.
- `place.kind`: `torso | leg | arm | neck | band | free`; `band` — притачной пояс: кольцо вокруг торса, x = середина полосы.
  Воротник — `neck` с `zero: 'cf' | 'cb'` (где x = 0) и `arc`: кольцо ровно своей длины; у `cb` угол идёт в обратную сторону (−x → правая сторона модели).
  Дуговые полосы (`ringArc`): верх короче низа — центр сверху (`dir: 1`, стойка, контурный пояс), длиннее — снизу (`dir: −1`, воронка).
- Мета стороны: `fold` — линия сгиба (припуск = обтачка), `lap` — заход застёжки (в обхват не входит). Шов `closure: true` — застёжка: в 3D сшита, в пошиве — петля/пуговица.
- Генератор может вернуть `stepLabels`/`stepNotes` (тексты шагов пошива по `seam.order`), `trims` (фурнитура из конструкции: молния, пуговицы) и `piece.matPreset` (своя ткань детали).
- Шов `ease: true` — с намеренной посадкой (сгиб у колена); допуск сверки — `seamTol(s)` (2,2 см вместо 0,35).
- `piece.lining` — деталь подкладки (тоже `inner`). Добавленные вручную шаги пошива — `g.extraSteps.{labels,notes}` (генератор их не трогает,
  но перестройка изделия параметрами сбрасывает ручные детали, как и любые правки).
- `m.stock` — длина отреза у пользователя, м (0 — рулон); `stockFit(r)` в `cost.js`. Себестоимость — `garmentCost(g, mats, opt)`, ставка — `S.settings.laborRate`.

## Проверенные решения и почему
- Обручи (hoop) только для «кольцевых» краёв (`RING_EDGES`: пояс, низ, низ рукава, горловина, пройма, край) —
  на большом контуре распашного пальто обруч стягивал вещь с плеч.
- Статическое трение обязательно: без него тяжёлое распашное пальто сползало под весом рукавов.
- Обёртка рукава/брючины нормирована по ширине ряда — иначе шов закрывался через руку и рука выходила из рукава.
- Руки манекена по умолчанию отведены на 24°: при 14° слои застревали в подмышке.
- Брюки: спинка подгоняется к переду по длине бокового (опусканием верха у бока) и шагового шва (опусканием шаговой точки) — швы сходятся < 0,3 см.
- Выступ пояса под пуговицу — припуском на правом конце, а не частью полосы: иначе в 3D кольцо пояса длиннее линии притачивания и разводит средний шов.
- Джинсы: свобода по линии пояса ~1,5 см (у брюк 3,6) — иначе пояс оседает на бёдра.
- Воротник: кольцо в 3D — ровно длины воротника, иначе концы не сходятся по середине и `seamRev` переворачивает шов (зазор 10 см).
  С воротником горловина переда не глубже 9 см — на глубокий вырез стойку не притачать.
- Контурный пояс (низкая посадка) — дуга кольца, верх короче низа на разницу обхватов; кроится с обтачкой. В 3D ставится по дуге
  (`place.arc`: центр, радиус, длина низа), иначе кольцо считалось бы по габариту дуги.

## Известные ограничения
- Самопересечение — частицами (радиус ~1,15 см), края/швы исключены. Тонкие складки ещё могут проходить.
- Раскладка — однослойная, жадная; 50–70 % для одной вещи, тираж из нескольких размеров заметно лучше.
- PDF: линии — вектор; подписи — однобитные маски 400 dpi (кириллица без встраивания шрифта). Мелкие потоки PDF сжимать синхронно
  (`RunLengthDecode`), не `CompressionStream`: сотни асинхронных сжатий растягиваются на минуты.
- TypeScript — только проверка JSDoc в нестрогом режиме, UI пока без неё; нет WASM; решатель ~13–16 мс на шаг при 4,5 тыс. точек.
